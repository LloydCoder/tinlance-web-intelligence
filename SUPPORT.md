# Support

Tinlyt is actively developed. The repository is not a declaration of general availability, and no production support SLA is offered.

## Where to ask

| Need | Channel |
| --- | --- |
| Reproducible bug | [Open a bug report](https://github.com/LloydCoder/tinlance-web-intelligence/issues/new?template=bug_report.yml) |
| Feature proposal | [Open a feature request](https://github.com/LloydCoder/tinlance-web-intelligence/issues/new?template=feature_request.yml) |
| API and integration guidance | Start with [docs/README.md](docs/README.md) and the relevant API contract. |
| Contribution workflow | [CONTRIBUTING.md](CONTRIBUTING.md) |
| Security vulnerability | Follow [SECURITY.md](SECURITY.md); do not report exploitable details publicly. |
| Conduct concern | Follow private reporting instructions in [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). |

## Before opening an issue

- Search existing issues and documentation.
- Include the relevant commit, environment, Python/Node versions, and exact command.
- Provide a minimal reproduction and expected versus actual behavior.
- Remove access tokens, passwords, private URLs, personal information, and customer evidence.
- State which checks you ran and their results.

## Service availability

A public product site or a green repository workflow does not establish that the API is deployed, authenticated, or available for customer use. Deployment status, private-beta authorization, and general availability are tracked separately in [private-beta readiness](docs/operations/private-beta-readiness.md).
